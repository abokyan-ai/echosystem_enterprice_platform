# CMP-06 — Deterministic Compilation

Date: 2026-10-11. Status: **DEFERRED / NOT VERIFIED**. No compiler/comparison/example scenario was executed.

## Audit and enforced scope

CMP-01 already copies explicit phase lists to tuples, freezes descriptor/context/result/state, executes sequentially and preserves diagnostics/outcomes. MOD-04 already defines semantic-ID/numeric-version canonical order and same_membership/same_supported_content. CMP-03 has independent caller-owned request-local IR IDs and identity-sorted committed collections; CMP-05 emits canonical type order, owns gated atomic staging/collision handling and reuses CMP-04 exact immutable fields/constraints/references. No current compilation path reads time/random/PID/locale/CWD/filesystem/registry/database/HTTP settings. Source sidecars are presentation only.

Identified gaps: arbitrary mutable phase implementations/options could survive frozen outer composition; captured descriptors/options could drift after construction; equivalent binding mappings with different assignment order had different configuration equality; default envelope equality correctly used original request identity and could not compare equivalent independently accepted requests. CMP-06 fixes these boundaries in existing compiler-core rather than adding another compiler/policy switch/scheduler. Mandatory determinism is expressed through existing contracts and checks; a policy object with no selectable rules would duplicate them.

## Explicit immutable phase configuration

ModelCompiler still accepts an explicitly ordered tuple/list and copies it; unordered collections/generators/live option containers are rejected. Each configured phase must now be a frozen dataclass implementing the same descriptor/execute protocol. Capture all declared fields in declaration order; approved options are exact immutable primitive None/bool/int/str/bytes, existing immutable compiler/kernel/type value objects, current compiler enums and ordered tuples of these. No arbitrary metadata maps, float, mutable list/dict/set, custom service/callable, open frozen object or bare frozenset option. Existing descriptor capability/target frozensets remain supported because their closed contract uses membership, not iteration for scheduling. Expanding the option vocabulary needs a concrete owned immutable contract, never a generic object serialization framework.

ModelCompiler snapshots descriptors, implementation classes and complete approved configuration values. Audit entire composition before any phase executes and again after each phase returns a valid result. Changed options, descriptor, phase implementation type or composition length/type produce FAILED/CMP-030 without committing that phase's outputs. Pre-execution drift skips every phase, executed=False. During execution drift retains returned original diagnostics, records the actual executing phase FAILED/executed=True, associates changed configuration diagnostics with affected phase and blocks later phases. Mutation of another phase also yields an error on the executing phase. Prior immutable internal state survives; unsuccessful final result still exposes no successful preparation/artifacts.

Mutable/unsupported/duplicate/forward/cyclic phase configuration at construction raises existing ValueError-compatible CompilationConfigurationError with `.diagnostics` containing actual CMP-029/ERROR. It is structured constructor rejection, not a fabricated CompilationResult. Invalid request roots still follow CMP-001; malformed individual owned values retain their constructor errors. Unconfigured prerequisites remain CMP-007/INCOMPLETE/executed=False. No topological sort or arbitrary alphabetical precedence: ordered phases are semantic configuration; changing independent phase order is different configuration.

This intentionally tightens extension admission: prior mutable Protocol-only phases need frozen dataclass/configuration adaptation. Built-in preparation and TypeCompilerPass satisfy the rule. Existing executable tests/history remain unchanged; future fixtures using mutable phase doubles require adaptation when execution is authorized. Frozen fields do not prove arbitrary third-party execute methods avoid ambient reads, hidden class state, monkeypatching or bad transformations; extension implementation determinism remains an explicit obligation, with unsupported production capabilities not certified. The guard detects actual captured-contract drift, not arbitrary runtime nondeterminism.

## Type pass, identity and ordering

TypeCompilerPass canonicalizes its explicit exact identity bindings by semantic-ID/numeric-version coordinates at construction, copying the caller sequence. This canonicalizes a mapping configuration only; MOD-04 remains the sole definition-order owner. Missing/extraneous binding diagnostics, per-type lowering, field processing and collision diagnostics retain original canonical/field/emission order. Multiple exact versions survive; no latest-version policy. No registry lookup/ref closure/recursion. Original payload values, decimal precision, presence/nullability and versionless ElementRef unchanged.

Equivalent configuration requires the same explicit mapping of exact source refs to independent caller tokens. CMP-03 token scope is one original CompilationRequest; identical token strings in separate invocations are allowed, and no identity is generated from semantic names/UUIDs/source paths/time/hash/address/counter. Caller-selected tokens may differ, in which case configuration/IR identity comparison differs. Identity/evidence authorization still requires exact original request/model/state; semantic comparison never substitutes for those guards.

Phase output preserves canonical definition order. Committed state remains CMP-03 representation-ID order, independent of candidate arrival and duplicate overwrite. These are distinct documented ordering contracts. Field order and foundation-payload origin order are meaningful and preserved, not sorted. Diagnostic order is original prerequisite order, configured phase order, canonical type order, field order, original lowerer/factory emission and final commit/result diagnosis. Never sort localized message/severity/timestamp or collapse repeated occurrences. Existing atomic merge/collision/state transition and authoritative SUCCEEDED/FAILED/INCOMPLETE statuses remain.

## Supported semantic comparison

CompilationResultEquivalence is a stateless frozen value exposing five explicit operations; it does not execute the compiler, compare bytes, authorize input, or produce a reproducibility certificate.

| Operation | Compared fields | Limits |
|---|---|---|
| requests | Actual original VALID/READY evidence bound to each own model; supported context/target; MOD-04 same_supported_content | Same membership alone is insufficient; evidence/stage/report identity is not comparison content |
| configurations | Unchanged captured options, ordered descriptors and same in-process phase implementation classes | No package/compiler version identity; same installed implementation remains a condition |
| ir_envelopes | Exact collection order, explicit IR IDs, V0/kind/context, actual typed payload equality, exact ordered origins, model_wide/producer and equivalent independently bound requests | Excludes original request object identity and source sidecars for comparison only; handoff still requires original identity |
| results | Authoritative status/target/diagnostic semantic scope, ordered diagnostics and phase outcomes, supported successful preparation content/context | Compiler result observables only; failed/incomplete results omit preparation, so this alone cannot prove equivalent input; original validation reports/physical presentation and internal IR are not exposed/comparable here |
| states | Supported prepared content/context, ordered outcomes and semantic IR collection | Explicit internal-state comparison, no change to final result/IR exposure contract |

Diagnostic semantic comparison retains code/severity/phase/exact reference/cause, actual origin, semantic/artifact/related targets in declared order, context and IR ID. Excludes message text, human reason text, authoring paths/related paths, loader physical filenames/spans and diagnostic_context source sidecars. Its actual semantic_context remains compared. Phase comparison retains actual descriptor/status/executed and ordered diagnostic semantics. Semantic equality is separate from presentation equality; original messages/reasons/source associations remain in production reports untouched.

Current foundation/type payloads have actual immutable equality. No concrete artifact payload equality contract exists: results/states with any actual artifacts raise ValueError explicitly, rather than comparing metadata and claiming equivalence. Wrong comparator roots raise TypeError. Methods return False for differing supported semantic fields/configuration, invalid/unbound evidence or configuration drift. To reason about a full supported run, independently establish requests/configurations plus results and available internal IR/state; comparing two failed result observables alone cannot establish original canonical input equivalence.

MOD-04 same_supported_content covers only the actual captured type host/data vocabulary, not missing full TYPE-01/richer facets. same_membership compares only scope/exact refs. No universal snapshot equality from count/QName/repr/string/hash/filepath, no content fingerprint or canonical encoding. Implementation classes are in-process comparison scope, not portable compiler version IDs.
